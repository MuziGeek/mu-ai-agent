### 核实过的 API 事实（字节码级，后续别重复踩）

- 真实包路径是 `org.springframework.ai.rag.preretrieval.query.{transformation,expansion}.X`
  （不是直觉的 `rag.query.transformer`），`spring-ai-rag:1.1.8` 已在 compile classpath
- 四个组件的 builder 都要 **`ChatClient.Builder`**（不是 `ChatClient`），可共用一个实例：
  已确认 `Builder.chatClientBuilder(...)` 只是存字段转发，构造器未改写传入的 builder
- `RetrievalAugmentationAdvisor` 执行顺序：串行跑 `queryTransformers` → `queryExpander.expand()`
  → 每个 Query 并行检索 → `documentJoiner.join()` → `queryAugmenter.augment()`
- **空值行为（容易踩）**：
  - `queryTransformers(null)` → `Assert.noNullElements(Collection)` 要求集合非 null → **必须传空列表**
  - `queryExpander(null)` → Builder 只 `putfield` 不校验，`before` 里是 `ifnull` 跳过 → **安全**
  - `documentRetriever` 不能为 null（构造器直接断言）；`documentJoiner`/`queryAugmenter` 有兜底
- `MessageChatMemoryAdvisor` 默认 order = **-2147482648** = `HIGHEST_PRECEDENCE + 1000`（字节码确认）
- `ContextualQueryAugmenter.Builder`：`promptTemplate` / `emptyContextPromptTemplate` /
  `allowEmptyContext` / `documentFormatter`；默认模板是**英文**的，且 `allowEmptyContext` 默认 **false**
- `PromptTemplate` 在 **spring-ai-model** jar 里（不在 client-chat），`PromptTemplate.builder().template(String).build()`
- `QueryTransformer` / `QueryExpander` 都是**函数式接口**（抽象 `transform`/`expand` + default `apply`）
  → 测试里可直接用 `q -> q` 当桩

### 设计取舍（写进注释了，这里留个索引）

- 转换器**不单独注册 Bean**，装配结果收敛到 `PreRetrievalPipeline` 一个 record →
  链路内容可直接断言，不必反射翻 `RetrievalAugmentationAdvisor` 的私有字段
