## 环境观察：`refs/remotes/origin/*` 在本环境写不进去

**现象**：`mu-ai-agent` 与 `muzi-blog` 推送后，`git status -sb` 分别显示
`[origin/main: gone]` 和 `[ahead 1]`，`git branch -avv` 同；但
`git ls-remote origin refs/heads/main` 与 `git rev-parse main` **SHA 完全相同**，
远端确实已收到提交。

**排查**：`remote.origin.fetch` 配置正常（`+refs/heads/*:refs/remotes/origin/*`），
但 `.git/refs/remotes/` 目录**根本不存在**、`packed-refs` 里也无 remote 引用。
反复 `git fetch origin` 每次都报 `* [new branch]  main -> origin/main`，
`.git/refs/remotes/origin/` 仍不出现；手动 `git update-ref refs/remotes/origin/main <sha>`
报「写入成功」但状态照旧。

**结论**：沙箱对 `.git/refs/remotes/` 的写入不生效（`.git/refs/heads/` 正常，commit 无碍），
属**本地显示假象，不影响推送结果**。判断同步状态一律看
`git ls-remote origin refs/heads/main` 与本地 SHA 对比，不要信 `[gone]` / `[ahead N]`。
